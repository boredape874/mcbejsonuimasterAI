## 화면 기준

- **사용 목적:** Bedrock 제작자가 화면을 보며 요소를 움직이고 Codex에 같은 선택을 전달한다.
- **위계:** 중앙 편집 화면을 가장 넓게 두고, 그 위에 작업 영역 설정과 정렬 도구를 나눈다. 왼쪽 활동 메뉴·팩 탐색기는 화면과 요소를 선택하고, 중앙 탭은 비주얼·JSON·공유 게임 화면을 전환한다. 오른쪽은 선택 속성과 Codex 대화다.
- **색:** bridge. v2 공식 편집기 이미지에서 참고한 짙은 회색 작업대, 파란 주요 작업 버튼과 선택 표시. 밝은 테마도 선택하며 자동 정렬선은 자주색입니다. 안전 영역은 옅은 황색으로 표시하고 RP 화면 색은 유지한다.
- **깊이:** 패널 구분은 옅은 테두리로 표현한다. 편집 화면과 대화 상자의 그림자는 콘텐츠 경계를 알려 준다.
- **글자:** 한국어 시스템 글꼴과 14px 본문을 사용한다. 요소 이름·좌표는 고정폭 글꼴이다. 게임 글꼴과 브라우저 대체 글꼴의 증거를 구분한다.
- **간격:** 메뉴는 4/8px 단위를 중심으로 배치한다. 속성은 위치·모양·고급 배치로 묶고 고급 항목은 접는다.
- **입력:** 기존 네이티브 button, select, details, dialog를 사용한다. 포커스, 비활성 상태, 빈 목록과 오류 안내를 유지한다.

기기 설정·비교·안전 영역과 현재 편집기 편의 기능은 [기기별 미리보기 기준](90-studio-device-preview.md)에 정리했습니다. 정렬 도구는 중앙의 ‘정렬’ 창에서 사용합니다.

## 정렬 계약

계산은 확대 배율과 독립된 게임 UI 단위다. 기본 격자는 8px이며 1/4/8/16px를 선택한다. 같은 부모의 보이는 요소와 부모 경계를 후보로 삼고, 화면에서 6px 이내인 가장자리·가운데·동일 간격을 먼저 맞춘다. 후보가 없으면 격자로 맞춘다. Alt는 스냅을 끄고 Shift는 이동 축을 제한한다.

Shift/Ctrl 클릭으로 최대 64개를 선택한다. 부모와 자식을 동시에 선택해 두 번 이동하는 상황은 피한다. 한 요소 정렬은 부모 기준, 여러 요소 정렬은 선택 묶음의 경계 기준이다. 동일 간격은 크기가 다른 요소도 양 끝을 유지하며 빈 간격을 같게 한다. 그리드 배치는 가장 넓고 높은 요소를 셀 기준으로 쓰며 목록 순서를 유지한다.

일괄 편집은 같은 원본 파일에서만 가능하다. 모든 원본 위치·해시·revision과 IR/바인딩 소유권을 먼저 검사하고 한 번 저장한다. 공통 원본을 공유하는 인스턴스는 일괄 수정하지 않는다. 한 번의 정렬·배치·묶음 이동은 한 번에 실행 취소한다.

복제는 inline JSONC 선언과 하위 구조를 보존하고 위치를 8px 이동한다. BP 콜백이나 컬렉션 인덱스를 자동 재배선하지 않는다. 요소 잠금·목록 접기는 브라우저 편집 기능이며 게임 파일에 쓰지 않는다. 팩·화면 전환 시 초기화된다.

Codex 선택 요약은 최대 16개이며 전체 선택 수를 함께 전달한다. 더 큰 선택은 inspect가 필요하다. 미리보기와 정렬 성공은 Bedrock 런타임 검증을 대신하지 않는다.

## 브라우저 검증 목록

실제 클릭·드래그로 자동 정렬선, 다중 선택, 묶음 이동, 정렬, 동일 간격, 그리드 배치, 일괄 실행 취소, 복제, 키보드 이동, 이동 취소, 검색·접기·잠금과 설정 대화 상자를 확인한다. 1366/1600/1920px 창과 DPR 2에서 겹침, 가로 넘침과 대화 입력 영역을 확인한다. 테스트는 별도 RP 사본에서 수행한다.

## bridge. v2 구성 적용

2026-10-04에 [공식 웹 앱](https://editor.bridge-core.app/)의 v2.7.54와 [공식 기능 문서](https://bridge-core.github.io/editor-docs/features/), [공식 시작 가이드의 편집기 이미지](https://bridge-core.github.io/editor-docs/getting-started/#code-editor)를 확인했습니다. 가이드 이미지는 v2.1.5이며 배치 참고로 사용했습니다. 활동 메뉴, 팩 탐색기, 중앙 편집 탭과 하단 검사 영역을 자체 HTML/CSS로 구현했습니다. [bridge. 원본](https://github.com/bridge-core/editor)은 GPL-3.0이며 실행 코드·아이콘·로고를 복사하거나 의존성으로 추가하지 않았습니다.

- 활동 메뉴: 탐색기 표시, 화면 검색, Codex 열기, 검사 결과, 테마, 정렬 설정을 실제 동작에 연결합니다. Ctrl+P는 화면 검색, Ctrl+Shift+E는 탐색기를 접습니다.
- 중앙 JSON 탭: 선택 요소의 실제 원본 파일을 읽고 JSONC 문법과 SHA-256을 확인한 뒤 저장합니다. 줄 번호·Ctrl+S·미저장 표시·변경 버리기를 제공합니다. 브라우저 기본 텍스트 편집기이며 Monaco 자동 완성·문법 강조는 구현하지 않았습니다.
- 미저장 보호: 비주얼·게임 탭으로 전환해도 버퍼를 유지합니다. 팩·화면 변경은 저장 또는 변경 버리기 전까지 막고, 브라우저 이탈 시 기본 경고를 사용합니다. 외부 변경은 저장할 때 해시 충돌로 거절합니다. 원본 JSON 직접 수정은 고급 작업이며 생성 파일은 IR에서 수정해야 합니다.
- 탐색기와 속성 패널 경계를 드래그하거나 포커스 후 방향키로 조절합니다. 너비와 테마는 브라우저에 저장합니다. 좁은 창에서는 패널을 아래로 배치합니다.
- 프로젝트 메뉴: 팩 열기, 새 프로젝트, PNG 저장을 모아 편집 화면의 버튼 밀도를 줄였습니다.
- 기본 화면: 속성 패널만 열고 모양·고급 항목을 접습니다. 자주 쓰는 정렬·복사·붙여넣기만 도구줄에 두며 세부 편집은 ‘더 보기’, 보기·기기·스냅·함께 보기 설정은 ‘보기 설정’에 모읍니다.
- 클립보드: Ctrl+C/V/X, Delete, Ctrl+A와 실행 취소를 지원합니다. 텍스트 입력은 네이티브 편집을 유지하고 요소 클립보드는 원본 JSONC 스냅샷을 보관합니다. 부모·자식 중복 선택, IR 소유권, 해시·revision 충돌, 동적 위치와 다른 RP의 에셋을 검사합니다.
- Codex: 상단에는 현재 Studio 연결/작업 상태, 대화 패널에는 제목과 메시지 수를 보여 줍니다. ID·계정·시작 시각은 접힌 세션 정보에서 확인합니다. 데스크톱 현재 채팅과 Studio 세션을 구분합니다.

별도 QA 팩에서 JSON 저장·잘못된 문법 거절·버퍼 보호, 검색, 탐색기 접기, 테마, 패널 조절, 정렬·크기 통일, PNG 저장·캡처 해상도 읽기, 화면 이동과 기기별 비교를 실제 브라우저로 확인했습니다. 게임 입력과 실제 기기 GUI 배율은 이 검증에 포함하지 않습니다.

추가 QA에서는 Ctrl+C/V/X, 반복 붙여넣기, Delete/undo, Ctrl+A와 입력칸의 텍스트 클립보드 보존을 실제 Edge에서 확인했습니다. 실제 Codex 연결 상태를 확인했고, 제목·thread/turn ID·ID 복사·작업/오류 표시는 모의 응답으로 검사했습니다. 새 AI 요청을 실제 모델에 보내는 검증은 수행하지 않았습니다. 390/768/1280/1600/1920px 화면과 DPR 2에서 배치와 가로 넘침을 확인합니다.


## 기존 Codex 세션과 단순한 기본 화면

상단 Codex 상태 버튼과 대화 패널의 ‘세션 선택’에서 같은 Codex 홈의 로컬 대화를 불러옵니다. 제목 검색, 최근 수정 순서, 40개씩 더 불러오기, 보관된 대화 조회를 지원합니다. 모든 sourceKinds를 명시해 기본 API 필터가 숨기는 App Server·exec·하위 에이전트 세션도 표시합니다. 제목은 thread.name을 그대로 쓰고, 제목이 없는 경우에만 preview를 사용합니다. 다른 프로젝트도 목록에 포함됩니다. 클라우드 및 다른 PC의 대화는 이 로컬 API의 범위에 포함되지 않습니다.

‘열린 팩 작업으로 연결’은 thread/read로 실행 상태를 확인한 후 thread/resume을 사용합니다. 기존 thread ID와 대화 기록을 유지하고 작업 폴더·sandbox·Studio MCP·개발 지침을 현재 팩으로 설정합니다. 이 변경은 선택 창에서 설명합니다. 연결만으로 turn/start를 실행하지 않으며 실제 요청은 사용자가 메시지를 보낼 때만 시작합니다. 다른 창에서 같은 대화를 실행 중이면 작업을 마친 뒤 연결해야 합니다. 로컬 App Server의 상태는 다른 프로세스의 실행 상태를 모두 보장하지 않습니다.

대화 표시에는 최근 20개 turn에서 사용자·AI 메시지 최대 60개를 읽고 각 메시지 길이를 제한합니다. 명령 출력·도구 기록은 채팅에 넣지 않습니다. 이전 기록이 더 있으면 ‘최근 대화만 표시’를 알립니다. 실행 중인 세션 연결과 작업 중 대화 전환은 거절하고, 실패하면 현재 연결과 표시 기록을 유지합니다. 보관된 대화는 목록에서 조회하며 연결 전 Codex 앱에서 보관을 해제합니다. ‘새 대화’는 기존 기록을 삭제하지 않고 Studio 연결을 비웁니다. 서버 재시작 후에는 세션을 다시 선택합니다.

편집 화면은 요소/화면 탐색 탭으로 한 목록만 표시합니다. 화면을 선택하면 요소 탭으로 돌아옵니다. 요소 추가는 하나의 메뉴, 복사·붙여넣기는 ‘더 보기’와 기존 단축키로 제공합니다. 삭제는 상단 ‘삭제 ⌫’와 Delete/Backspace로 실행합니다. 기기·확대·정렬 도구는 한 줄에 모으고 중복 파일 경로와 상시 선택 안내를 줄였습니다. JSON 미저장 표시는 계속 표시합니다.

계약은 [OpenAI 공식 App Server 문서](https://learn.chatgpt.com/docs/app-server)의 thread/list·thread/read·thread/resume·thread/turns/list와 설치된 Codex CLI 0.160.0의 생성 JSON 스키마로 확인했습니다. 기존 세션 목록/다음 페이지/개별 조회는 실제 로컬 CLI로 검증했습니다. 연결·기록 복원·실행 중 차단·실패 보존은 모의 프로토콜 및 별도 RP 브라우저 QA로 검사했으며, 기존 실제 대화에 모델 요청을 보내지는 않았습니다.
